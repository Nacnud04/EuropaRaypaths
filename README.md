# A Fast, Coherent, 3D Radar Sounder Simulator for Complex Subsurfaces at Planetary Scales

A fast GPU-enabled radar simulator for modeling complex subsurfaces at planetary scales. Built with Europa Clipper's REASON instrument in mind, but works for any orbital radar sounder.

## What is this?

This is a radar sounder simulator. It is designed for modeling the coherent response of any subsurface target within a planetary body. It is specifically designed for modeling km-scale cracks, brine, and ductile ice within the interior of Europa. As long as the altitude of the spacecraft is high enough such that the incoherent return is negligible, and there are no double-reflections this simulator should be able to model the signal.

To achieve the above, the simulator makes significant assumptions about the nature of the received energy. In particular, we reduce computational cost compared to other planetary scale simulators by stating that the incoherent signal is at or below the noise floor, and there is insignificant energy radiating between scatterers or in the non-specular direction. This allows us to decrease the quantity of raypaths required when the domain size increases enabling rapid production of many subsurface instances, enabling problem adaptability, inversion and uncertainty quantification.

## Getting Started

### Requirements

- NVIDIA GPU (CUDA capable)
- Python 3.x

### Installation

1. Clone the repository
```
git clone https://github.com/Nacnud04/EuropaRaypaths.git
cd EuropaRaypaths
```

2. Update your ~/.bashrc with your GPU setup:
```
export nGPU={number of NVIDIA GPUs installed}
```

3. Update compilation parameters:

Go into `src/CUDA/compile.sh` and update simulation parameters based on system name.

4. Run an example:

It is easiest to start by running a validation example within the `examples/UNIT_TESTS` directory to ensure the simulator is performing as expected. Some empty directories may need to be created for program outputs (`figures`,`rdrgrm`, etc.). Start by running the `fresnel_zone` and `subsurface_offset_target` examples. 

Most examples should have a `run.sh` to make things easy.


## Basic Usage

Check the `examples/` directory for sample simulations. A simulation is run as follows:

```
../../../src/CUDA/sim {INPUT_PARAMETERS.json} {FACET_GEOMETRY.fct} {TARGET_GEOMETRY.txt} {OUTPUT_DIRECTORY}
```

To understand how to construct each simulator input, refer to the `UNIT_TEST` examples. 

In general, `INPUT_PARAMETERS.json` contains all radar system parameters (both transmit and receive), bulk material parameters, system processing parameters (assumptions, coherent/incoherent, etc) as well as some coefficients. It also may contain information such as other files for the code to reference. These other files could include receive opening window information or subsurface attenuation geometry. This file is usually generated by `src/PYTHON/param_gen.py`.

`FACET_GEOMETRY.fct` can be generated by `src/PYTHON/simple_surfaces.py`. Facet information is structured where each line represents a facet, and that line contains the center position in 3D space followed by the 3 orthonormal basis vectors for the facet. 

`TARGET_GEOMETRY.txt` can be structured a number of ways, depending on the simplicity of the problem. Similarly to the facets each row defines an individual target. The options for how to define the targets are shown in the following table:
| Entries | Target Position | Normal Vector | Radiation Pattern | Description |
|---------|---|---|---|---|
| **3** | x, y, z | Assumed straight up | Identical to surface facets | Default configuration; target normal points upward |
| **4** | x, y, z | Assumed straight up | Previously encoded pattern | Same as 3-entry, but uses a custom radiation pattern |
| **6** | x, y, z | Specified | Identical to surface facets | Explicit normal vector; uses facet radiation pattern |
| **7** | x, y, z | Specified | Previously encoded pattern | Full specification; both normal and radiation pattern are custom |

`OUTPUT_DIRECTORY` denotes the directory for the simulation output traces. Each trace is immediately output as an independent file to ensure that in case of a crash or power loss during operation progress will not be wasted.

## What This Can Do

- Simulate entire flight paths (hundreds of kilometers if needed)
- Model layered or non-layered, complex subsurfaces.
- Generate synthetic radargrams you can focus and interpret like real data
- Run on modest GPU memory (we manage ~500,000x less memory than finite-difference approaches)
- Run quickly only taking a few seconds per trace even in complex problems.

## What This Can't Do

- Model wave refraction through subsurface boundaries
- Simulate double reflections
- Simulate for very low altitudes, where incoherent energy may become significant

These tradeoffs lets us run fast simulations over planetary scales while keeping nearly all the information that matters for interpretation.

## Validation

The simulator has been tested against:
- Analytical solutions for standard radar physics scenarios
- Real SHARAD data from Mars (Korolev Crater)
- Europa Clipper REASON instrument parameters

Performance: within 1 dB of expected results across all test cases.
